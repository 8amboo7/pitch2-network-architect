โครงสร้าง 3 ชั้น: Core / Distribution / Access

เปรียบเหมือนระบบถนน: Access คือซอยหน้าบ้าน Distribution คือถนนสายหลักของแต่ละย่าน และ Core คือทางด่วนที่เชื่อมทุกย่านเข้าหากัน ออกแบบ HA ครบทั้งสามชั้น: Core และ Distribution มีอุปกรณ์เป็นคู่ ส่วน Access ใช้ Stack และ Uplink แยกเส้นทาง กดปุ่ม “มุมมองแบ่งชั้น” ในภาพ 3 มิติเพื่อดูแต่ละชั้นแยกกัน

Core Layer HA (2 ตัว)

อยู่ในห้อง Server ชั้น 2 ทำหน้าที่ส่งข้อมูลความเร็วสูง (40/100G) ระหว่างบล็อกสำนักงาน บล็อกคลัง บล็อก Server และ Firewall ไม่ต่ออุปกรณ์ผู้ใช้ตรง ทั้งสองตัวทำงานพร้อมกันแบบ MLAG ถ้าตัวหนึ่งเสีย อีกตัวรับงานแทนในเวลาไม่ถึง 1 วินาที

Distribution Layer HA (2 + 2 + Server 2)

แต่ละบล็อกมี Switch 2 ตัวเป็นคู่สำรอง รวมสายจาก Access เป็น Default Gateway ของ VLAN ด้วย VRRP และบังคับใช้ ACL ระหว่างกลุ่ม ทุก Access ต่อ Uplink ไป Distribution ทั้งสองตัว และ Distribution แต่ละตัวเชื่อม Core ทั้งคู่

Access Layer HA (21 ตัว)

แต่ละชั้นสำนักงานมี Switch 3 ตัวทำ Stack ส่วนคลังมี 3 โซน โซนละ 2 ตัวทำ Stack เป็นคู่สำรอง ทุก Stack มี Fiber 10G สองเส้นไป Distribution คนละตัว และกระจาย AP/อุปกรณ์สำคัญข้ามสมาชิก Stack

ทำไมไม่รวม Core กับ Distribution เป็นชั้นเดียว (Collapsed Core)? สำหรับ 400 คนก็ทำได้ แต่ APJC มีคลังที่ทำงานตลอดวันและมีแผนขยาย การแยก Distribution ของคลังออกมาทำให้งานบำรุงรักษาหรือปัญหาฝั่งสำนักงานไม่กระทบการยิงบาร์โค้ด และเพิ่มอาคาร/โซนใหม่ได้โดยต่อ Distribution คู่ใหม่เข้า Core ทันที

ทำไมต้องใช้ PoE

IP Phone 150 เครื่อง กล้อง 60 ตัว และ AP 46 ตัว รับไฟจาก Switch ผ่านสาย LAN เส้นเดียว ไม่ต้องเดินปลั๊กไฟไปบนฝ้าหรือเพดานคลังสูง ติดตั้งเร็วและถูกกว่า และเมื่อไฟดับ UPS ที่ตู้ Switch จะเลี้ยงโทรศัพท์ กล้อง และ Wi-Fi ต่อได้จากจุดเดียว กล้องยังบันทึกภาพได้แม้ไฟดับ

งบไฟ PoE ต่อชั้นโดยประมาณ: โทรศัพท์ 24 × 7 W + AP 6 × 25 W + กล้อง 5 × 12 W ≈ 380 W เราใช้ Switch PoE+ (802.3at) ชั้นละ 3 ตัว แต่ละตัวมีงบ ≥ 740 W จึงเหลือเผื่อการขยายและ AP รุ่นใหม่ที่กินไฟมากขึ้น

Redundancy: ถ้าอุปกรณ์แต่ละตัวเสีย จะเกิดอะไรขึ้น

ตารางนี้ใช้ตอบคำถาม “ถ้า Core เสียจะเป็นอย่างไร” และทุกบรรทัดลองดูได้จริงในปุ่มสถานการณ์ของภาพ 3 มิติ

การเชื่อมต่อสาขา: SD-WAN บน Internet 2 ทาง

ทุกสาขามีอุปกรณ์ SD-WAN Edge (Router + Firewall ในตัว) 1 ตัว ต่อ Internet 2 ทาง และสร้างอุโมงค์เข้ารหัสอัตโนมัติ

อุโมงค์หลักไป HQ

IPsec เข้ารหัส AES-256 วิ่งบน Internet ไปที่ Firewall ของ HQ ซึ่งทำหน้าที่เป็น Hub Firewall อนุญาตให้สาขาเข้าถึงเฉพาะ ERP, File Server และ IP-PBX เท่านั้น

Internet 2 ทางต่อสาขา

Fiber Broadband เป็นเส้นหลัก และ 4G/5G เป็นเส้นสำรอง SD-WAN วัด Latency/Packet Loss ตลอดเวลา และส่งทราฟฟิกสำคัญ (ERP, เสียง) ไปทางที่ดีที่สุดเอง

อุโมงค์สำรองไป Cloud DR

ตั้งไว้ล่วงหน้าแต่ไม่ใช้งานในภาวะปกติ เมื่อประกาศเปิด DR สาขาจะวิ่งไป ERP บน Cloud ได้ทันทีโดยไม่ต้องตั้งค่าใหม่ที่หน้างาน

Microsoft 365 ออกตรงที่สาขา

ทราฟฟิก M365 และ Internet ทั่วไปออกที่สาขาเลย (Local Breakout) ผ่านการกรองของ Edge ไม่ต้องอ้อมมา HQ ทำให้ลิงก์ของ HQ ไม่แน่น

ทำไมเลือก SD-WAN แทน MPLS? MPLS คุณภาพคงที่แต่ค่าเช่ารายเดือนสูงและใช้เวลาติดตั้งนาน SD-WAN ใช้ Internet ธรรมดาที่ถูกกว่า มีเส้นสำรอง 4G/5G ในตัว เพิ่มสาขาใหม่ได้ในวันเดียว และดูสถานะทุกสาขาได้จากหน้าจอเดียว สำหรับสาขา 30–40 คนที่ใช้ ERP และ M365 เป็นหลัก คุณภาพเพียงพอ

Security พื้นฐาน

ตำแหน่ง Firewall

Next-Generation Firewall 2 ตัวแบบ HA ตั้งระหว่าง Router ของ ISP ทั้งสองกับ Core Switch ทุกทราฟฟิกเข้า–ออก Internet ต้องผ่านจุดนี้ และเป็นปลายทางอุโมงค์ของสาขาและ Cloud DR ที่สาขามี Firewall ในตัว SD-WAN Edge ส่วน Cloud มี Virtual Firewall

Zone บน Firewall

OUTSIDE (Internet), INSIDE (VLAN พนักงาน/Server), GUEST, BRANCH-VPN และ CLOUD-DR แต่ละ Zone คุยกันได้เฉพาะที่กฎอนุญาต ค่าเริ่มต้นคือปฏิเสธทั้งหมด

การแยกเครือข่ายแขก

VLAN 90 ไม่มี Gateway บน Core เลย ทราฟฟิกแขกถูกส่งตรงไป Firewall ซึ่งอนุญาตเฉพาะออก Internet (HTTP/HTTPS/DNS) แขกจึงมองไม่เห็น ERP, กล้อง และเครื่องของพนักงาน รวมถึงมองไม่เห็นเครื่องแขกคนอื่น

ภายในเครือข่าย

802.1X/NAC ตรวจว่าเครื่องเป็นของบริษัทก่อนให้เข้า VLAN พนักงาน, DHCP Snooping, Dynamic ARP Inspection, BPDU Guard, ปิดพอร์ตที่ไม่ใช้ และเข้าจัดการอุปกรณ์ได้จาก VLAN 10 เท่านั้น

ทำไมต้องใช้ VLAN

VLAN แบ่ง Switch ตัวเดียวให้เป็นเหมือนหลายเครือข่ายแยกกัน ได้ 3 อย่าง: ความปลอดภัย (กลุ่มหนึ่งถูกเจาะ ไม่ลามไปกลุ่มอื่นเพราะต้องผ่านกฎ ACL/Firewall), ประสิทธิภาพ (Broadcast อยู่ในวงเล็ก ๆ กล้อง 60 ตัวที่ส่งภาพตลอดไม่แย่งแบนด์วิดท์โทรศัพท์) และการจัดการ (ตั้ง QoS ให้เสียง ตั้งกฎให้ Scanner เข้าได้แค่ ERP ตามกลุ่ม ไม่ต้องตามทีละเครื่อง) โดยไม่ต้องซื้อ Switch แยกให้แต่ละกลุ่ม

Disaster Recovery บน Cloud

อุปกรณ์คู่ในห้อง Server ป้องกันการเสียทีละตัว แต่ไม่ป้องกันเหตุที่ทำให้ทั้งห้องหายไป เช่น ไฟไหม้ น้ำท่วม หรือ Ransomware เข้ารหัสทุกเครื่อง DR บน Cloud คือสำเนาที่อยู่นอกอาคาร พร้อมเปิดใช้เมื่อจำเป็น

15 นาทีRPO ของ ERP: ข้อมูลหายไม่เกินนี้
1 ชั่วโมงRPO ของ File Server
4 ชั่วโมงRTO: เวลาจนใช้ ERP บน Cloud ได้
2 ครั้ง/ปีซ้อม DR จริง

รูปแบบ: Warm Standby (Pilot Light)

ฐานข้อมูล ERP ถูก Replicate ไป Cloud ต่อเนื่องทุก 5–15 นาทีผ่านอุโมงค์ IPsec ที่วิ่งจาก Firewall HQ ไป Virtual Firewall บน Cloud, File Server ส่ง Snapshot ทุกชั่วโมง เครื่อง App ของ ERP บน Cloud ถูกปิดไว้หรือเปิดเครื่องเล็กสุด จึงจ่ายค่า Cloud เฉพาะพื้นที่เก็บข้อมูลในภาวะปกติ นอกจากนี้มี Backup รายวันแบบ Immutable (ลบหรือแก้ไม่ได้ 30 วัน) แยกอีกชั้นเพื่อป้องกัน Ransomware ตามหลัก 3-2-1: ข้อมูล 3 ชุด สื่อ 2 แบบ อยู่นอกสถานที่ 1 ชุด

ขั้นตอนเมื่อประกาศเปิด DR

  1. ผู้บริหารและ IT Manager ประกาศเหตุ เมื่อประเมินว่า HQ ใช้งานไม่ได้เกินเวลาที่ยอมรับได้ (เช่น 2 ชั่วโมง)
  2. Promote ฐานข้อมูลสำรองบน Cloud เป็นตัวหลัก และขยายเครื่อง App ของ ERP ให้เต็มขนาด
  3. เปลี่ยน DNS ของ erp.apjc และ files.apjc ไปชี้ IP บน Cloud (10.100.20.x)
  4. SD-WAN ของทุกสาขาสลับไปใช้อุโมงค์สำรองที่ตั้งไว้แล้วไป Cloud DR อัตโนมัติ
  5. พนักงาน HQ ทำงานจากบ้านหรือสาขาผ่าน Client VPN ที่ต่อตรงเข้า Cloud, อีเมลและ Teams ใช้ต่อได้ตามปกติเพราะอยู่บน M365 อยู่แล้ว
  6. เมื่อ HQ กลับมา Replicate ข้อมูลย้อนกลับ (Failback) ในช่วงนอกเวลาทำงาน แล้วสลับ DNS กลับ
ลองกด “HQ ล่ม → เปิด DR” และ “Replication ไป Cloud” ในภาพ 3 มิติด้านบนเพื่อดูเส้นทางข้อมูลของแต่ละช่วง

เตรียมตอบคำถามกรรมการ

ทำไมต้องใช้ VLAN ซื้อ Switch แยกไม่ได้หรือ?

ได้ แต่ต้องซื้อและดูแล Switch 6–7 ชุดคู่ขนานกันทุกชั้น VLAN ให้ผลเดียวกันบน Switch ชุดเดียว แต่ละกลุ่มแยกขาดจากกันที่ Layer 2 และจะคุยข้ามกลุ่มได้ต้องผ่านกฎ ACL/Firewall ที่เรากำหนด ประหยัดกว่าและยืดหยุ่นกว่า ย้ายโต๊ะก็แค่เปลี่ยน VLAN ของพอร์ต

ถ้า Core เสียจะเกิดอะไรขึ้น?

มี Core 2 ตัวทำงานพร้อมกัน ทุก Distribution และ Firewall ต่อสายเข้าทั้ง 2 ตัวรวมเป็นลิงก์เดียว (MLAG) เมื่อตัวหนึ่งเสีย ลิงก์ที่เหลือรับทราฟฟิกทั้งหมดภายในไม่ถึง 1 วินาที ผู้ใช้ไม่รู้สึก ความเสี่ยงเดียวคือช่วงที่รอเปลี่ยนเครื่องเราไม่มีตัวสำรอง จึงต้องมีสัญญา MA แบบเปลี่ยนเครื่องในวันถัดไป (ลองกดสถานการณ์ “Core #1 เสีย”)

ทำไมต้องใช้ PoE?

อุปกรณ์กว่า 250 ชิ้น (โทรศัพท์ กล้อง AP) ได้ทั้งข้อมูลและไฟจากสายเส้นเดียว ไม่ต้องเดินปลั๊กไปเพดานคลังสูง ติดตั้งเร็ว ย้ายง่าย และเมื่อไฟดับ UPS ที่ตู้ Switch จะเลี้ยงทุกอย่างต่อ กล้องยังบันทึกได้ โทรศัพท์ยังโทรได้

ถ้า Internet ทั้ง 2 ISP ล่มพร้อมกันล่ะ?

โอกาสต่ำเพราะเลือกคนละผู้ให้บริการและคนละเส้นทางเข้าอาคาร ถ้าเกิดขึ้น ระบบภายใน HQ ทั้ง ERP, File, โทรศัพท์ภายใน และกล้องยังทำงาน สิ่งที่หยุดคือ M365 และการเชื่อมสาขา ถ้ายืดเยื้อ ผู้บริหารเลือกเปิด DR เพื่อให้สาขากลับมาใช้ ERP ผ่าน Cloud ได้

แขกต่อ Wi-Fi แล้วเข้ามาเจาะ ERP ได้ไหม?

ไม่ได้ VLAN แขกไม่มีเส้นทางไปเครือข่ายภายในเลย Gateway อยู่บน Firewall ซึ่งอนุญาตเฉพาะออก Internet และเปิด Client Isolation ทำให้แขกมองไม่เห็นกันเอง (กดสถานการณ์ “เส้นทาง Wi-Fi แขก”)

ทำไมทำ DR บน Cloud แทนการสร้างห้อง Server สำรองอีกแห่ง?

ห้อง Server สำรองต้องลงทุนอุปกรณ์ซ้ำเกือบทั้งชุด ค่าพื้นที่ ไฟ แอร์ และคนดูแล Cloud จ่ายเฉพาะพื้นที่เก็บข้อมูลในภาวะปกติ และจ่ายค่าเครื่องเต็มเฉพาะตอนซ้อมหรือเกิดเหตุจริง อีกทั้งอยู่ห่างจาก HQ คนละภูมิภาค ไม่เจอภัยเดียวกัน

Scanner หลุดบ่อยในคลังจะแก้อย่างไร?

ทำ Site Survey ก่อนและหลังติดตั้ง ใช้ AP แบบเสาอากาศทิศทางยิงลงระหว่างชั้นวาง เปิด 802.11r/k/v ให้ Scanner ย้าย AP ได้ใน < 50 มิลลิวินาที และให้ Controller ปรับช่องสัญญาณอัตโนมัติเมื่อสินค้าบนชั้นเปลี่ยน

รองรับคนเพิ่ม 30% ได้จริงหรือ?

พอร์ตต่อชั้น 144 รองรับ ~104 คน + AP + กล้อง + เครื่องพิมพ์ ยังเหลือ, VLAN พนักงาน /24 ต่อชั้น (254) และ Wi-Fi /22 (1,022), PoE ใช้ราวครึ่งของงบ ถ้าเกินกว่านั้นเพิ่ม Switch เข้า Stack ได้ทันทีโดยไม่กระทบชั้นอื่น
